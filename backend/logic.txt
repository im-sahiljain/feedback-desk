Feedback Classification System Documentation
1. System Overview
This system uses Zero-Shot Text Classification to automatically analyze customer feedback without needing a specific training dataset for your custom labels. It utilizes a deep learning model to understand the semantic meaning of text and map it to any categories you define.

Core Technology:

Model: Xenova/nli-deberta-v3-xsmall
Architecture: Microsoft DeBERTa V3 (Decoding-enhanced BERT with disentangled attention).
Format: ONNX (Optimized for running locally in Node.js/Browsers).
2. How It Works: The "Magic" of NLI
The model does not just "guess" keywords. It treats classification as a Natural Language Inference (NLI) problem.

The Mechanism
For every piece of feedback, the system constructs a pair of sentences:

Premise: The user's feedback text.
Example: "The dashboard takes forever to load."
Hypothesis: A sentence constructed using your label.
Template: "This example is {}."
Example: "This example is Performance."
The model then determines the probability that the Premise implies the Hypothesis.

If the model says "True" (Entailment) with high confidence (e.g., 98%), then the label applies.
If the model says "False" (Contradiction), the label does not apply.
3. Classification Dimensions
We perform three separate "passes" (classification runs) for every piece of feedback to extract different dimensions of information.

Pass 1: Categorization (Multi-Label)
Goal: Identify what the feedback is about.
Labels: ["Bug Report", "Performance", "Feature Request", "UI/UX", "Documentation", "Security", "General", "Billing"]
Logic:
The model compares the feedback against all labels independently.
Since a sentence can be both a "Bug Report" AND "UI/UX", we use Multi-Label mode.
The scores are independent (e.g., Bug: 0.9, UI: 0.8, Billing: 0.01).
Pass 2: Sentiment Analysis
Goal: Determine the user's emotional tone.
Labels: ["Positive", "Negative", "Neutral"]
Logic:
The model compares the feedback against these three options.
Single-Label mode is enforced: The scores must sum to 1 (softmax).
The label with the highest score wins.
Example: "Love the new feature" -> Implies "This is Positive" (Score: 0.99).
Pass 3: Priority Assignment
Goal: estimate urgency based on semantic severity.
Labels: ["High Priority", "Medium Priority", "Low Priority"]
Logic:
This is the most advanced use of Zero-Shot. We don't write rules like "if it says 'urgent' then High".
Instead, the model understands the semantic severity.
Example:
"The app crashes immediately" strongly implies "This is High Priority".
"Dark mode would be nice" weakly implies "High Priority" but strongly implies "Low Priority".
Single-Label mode picks the best fit.
4. Scoring & Confidence
Every classification returns a Confidence Score between 0 and 1.

> 0.90 (Very High): The model is extremely certain. (e.g., "Login is broken" -> Bug Report).
0.50 - 0.90 (Moderate): The model sees a connection but it might be vague.
< 0.50 (Low): The model is guessing; the text likely doesn't fit any label well.
Example Walkthrough
Input: "I cannot login to my account, it gives a 500 error."

Category Pass:

Hypothesis: "This is a Bug Report." -> 0.99 (Keep)
Hypothesis: "This is UI/UX." -> 0.12 (Discard)
Result: Bug Report
Sentiment Pass:

Hypothesis: "This is Negative." -> 0.98 (Winner)
Hypothesis: "This is Positive." -> 0.01
Result: Negative
Priority Pass:

Hypothesis: "This is High Priority." -> 0.95 (Winner) (Context: "Cannot login" is severe)
Result: High Priority
5. Why This Model? (nli-deberta-v3-xsmall)
We selected this specific model based on our benchmarks:

Context Aware: Unlike keyword search, it understands "The page does not load" is a Performance issue even if the word "performance" is never used.
Efficiency: It is a "quantized" (compressed) version (~40MB).
Inference Speed: ~0.2s per item (CPU).
RAM Usage: <500MB (Safe for Render/Heroku free tiers).
Accuracy: It outperformed larger API models in our specific test cases because DeBERTa V3 is architecturally superior for NLI tasks.
